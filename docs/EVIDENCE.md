## E. 한 줄 요약

- 문제 수치(71.5% 합산, 30분에 5,000ppm 까지, 2,000ppm 에서 나타날 수 있다, 1~2시간마다 1~2분 외기는 자동차연구원 "지침", 2시간 휴식 권고, 여름 에어컨 내기순환)는 전부 한국도로공사 발표 보도(2026.1, 2026.7)로 확인됨.
- DAW 의 한계와 제네시스 상담원 콜은 기아 매뉴얼, 그랜저 2026 매뉴얼, 제네시스 공식 페이지로 확인됨. DAW 발생 빈도 자료는 없음.
- 이미 있는 것: 모비스 스마트캐빈(2022, 양산 미확인), 일부 사양의 "CO₂ 자동 환기" 설정. 그랜저 2026 공조 매뉴얼에는 CO2·시간 기준 자동 외기 전환 없음. 숨은 "CO2 센서 없는 차에서 탄 사람 수로 추정" + "묻고 동의받기" + "졸음 경고 뒤 쉼터·쉼 모드"로 선을 긋는다.
- Pleos 숫자(그랜저 5월, 2030년 2천만 대, Gleo AI 제어)는 현대차그룹 뉴스룸 2026-04-30 로 확인됨.
- 졸음쉼터 데이터는 공공데이터포털 253곳(기준일 2026-02-25). 쉼터 설치 효과 수치는 범위 미확인으로 사용 금지.

## F. 숨 모델 (탑승 인원 기반 실내 CO2 추정)

검증일: 2026-11-10. 대상은 Contract.kt 의 WakeConfig 숨 모델 기본값(v0.5.0 기준: co2PerPersonLph 18, cabinVolumeL 3000, leakAch 2, freshAchMax 60(풍량 1단 25회/시간에서 최대 단까지 선형), windowAch 15, co2LimitPpm 2000, outdoorPpm 430, 시작 값 바깥 + 200 = 630ppm)과 기획서 문장이다. 원문 인용은 15단어 이내. "확인 경로"가 2차인 항목(원 논문이 유료이거나 차단되어 초록, 저자 공개본, 원 논문 표를 그대로 옮긴 다른 문서로 확인한 것)은 판정 칸에 적었다.

숨 모델 식: dC/dt = (인원 x co2PerPersonLph x 1e6) / cabinVolumeL - ACH x (C - outdoorPpm). C 는 ppm, 배출량은 L/시간, 부피는 L. 1명이면 생성 항이 시간당 6,000ppm 이다. 내기순환이면 ACH = leakAch, 외기면 leakAch + 풍량 단계에 따른 외기분(1단 25, 최대 단 60 사이 선형, 풍량 0 이면 9), 창문이 5% 이상 열리면 windowAch x min(열림/15, 3) 을 더한다.

### G-6. 기획서·영상 문장과 해외용 한 줄

써도 되는 문장 6개:

1. "현대차 취급설명서도 실내 순환을 오래 쓰면 탑승자가 내쉰 이산화탄소로 두통이나 졸음이 올 수 있다고 적고 있다." (F25)
2. "한 실험에서 내기순환 30분 뒤 실내 이산화탄소는 1명일 때 약 1,600ppm, 4명일 때 약 6,600ppm 이었다. 같은 30분이라도 몇 명이 탔느냐에 따라 다르다." (F13)
3. "숨은 CO2 센서 없이 탑승 인원, 내기·외기, 풍량, 창문 상태로 실내 이산화탄소를 추정한다. 측정값이 아니라 추정값이고, 화면에도 추정이라고 표시한다." (F-2 검산)
4. "이산화탄소가 판단력에 영향을 준다는 실험과 영향이 없었다는 실험이 모두 있다. 숨은 추정값을 환기가 부족하다는 신호로만 쓴다." (F20, F22)
5. "EU 규정이 졸음 운전 지표의 예로 드는 '미세 조향이 줄고 크고 빠른 보정이 느는' 패턴을 핸들 각도로 세어 보조 신호로만 쓴다. 기준값은 자체 설정이고 베타에서 조정한다." (G1, G6)
6. "EU 규정이 졸음 경고 시스템에 요구하는 것은 경고까지다. 졸음 뒤 공조를 바꾸는 차(중국 Voyah)와 휴게소 검색을 제안하는 차(메르세데스)는 있다. 숨은 이 둘과 공기 추정, 쉼터 경유지, 쉰 시간을 한마디 동의로 잇는다." (G11, G13, G14)

금지 문장 6개:

1. "세계 최초", "유일한", "아무도 하지 않은". 인원 기반 CO2 추정은 특허 출원(2018)이 있고, 시간 기준 자동 환기는 기아와 Voyah 에 양산돼 있다. (F26, F27, F29)
2. "실내 CO2 를 측정한다", "지금 2,140ppm 입니다" 같은 확정 수치. 추정이고 실측보다 1.2~1.5배 높게 나올 수 있다.
3. "CO2 가 2,000ppm 을 넘으면 졸린다", "CO2 가 졸음의 원인이다". 반대 결과(Zhang 2017)가 있다. "나타날 수 있다", "연구가 있다"까지.
4. "1,000ppm 에서 인지 능력 15% 감소, 1,400ppm 에서 50% 감소" 등 Allen 2016 의 수치. 원문에서 확인하지 못했다. Satish 의 결과를 운전이나 졸음으로 옮겨 말하는 것도 금지.
5. "현대 DAW 는 핸들 조작을 분석한다", "핸들 패턴으로 졸음을 정확히 감지한다". 매뉴얼은 "주행 패턴 등"까지만 적고, 숨 임계값은 검증되지 않았다.
6. "졸음운전이 전 세계 교통사고 사망의 N%", "WHO 에 따르면". WHO 수치에는 졸음 비율이 없다. "규제가 경고만 허용한다"도 금지(요구가 경고까지일 뿐이다).

해외 독자용 영어 한 줄 소개 후보 3개:

2. "Drowsiness warnings tell you to take a break. Kkaeugi handles the next ten minutes: fresh air, a slightly open window, and a rest stop added to your route, each only after you say yes."
3. "No CO2 sensor needed. Kkaeugi counts occupants, tracks recirculation, fan and window state, and suggests two minutes of outside air before the cabin gets stuffy."

### G-7. 숨 모델·핸들 신호 한 줄 요약

- 기본값 일곱 개는 문헌 범위 안이다. 외기 모드 최저 풍량의 바닥(25회/시간), 창문 환기(30 에서 15), outdoorPpm 430 은 v0.5.0 에 반영됐다.
- 모델은 실측(Mathur 2020)보다 1.2~1.5배 빨리 오른다. "추정"이라고 쓰고 ppm 을 확정값으로 말하지 않는다.
- CO2 와 졸음의 관계는 "나타날 수 있다" 수준. 반대 결과를 함께 적는다. 가장 안전한 근거는 현대차 매뉴얼 문장과 도로공사 발표다.
- 이미 있는 것: 기아 "자동 환기"(저온 30분), Voyah(20분마다 1분, 피로 감지 시 공조 자동 조절), 메르세데스(경고 뒤 휴게소 검색 제안), 인원 기반 CO2 추정 특허 출원(2018). 숨은 "처음"이 아니라 "한 흐름으로 잇는 앱"으로만 말한다.
- 핸들 신호는 EU 규정과 리뷰 논문이 말하는 패턴에 근거하지만 임계값은 자체 설정이다. 보조 신호로만 쓴다. v0.6.0 부터는 실험으로 내려 기본 꺼짐이다.

## H. 앱이 모르는 것 (v0.6.0, 2026-11-10)

새 근거는 없다. 이 절은 숨이 알 수 없는 것을 적어 두는 자리다. 아래 다섯 가지는 Pleos SDK(Vehicle 2.3.2, NaviHelper 3.0.5) AAR 을 javap 로 훑어 해당 신호를 주는 API 가 없음을 확인했다(`docs/API_FACTS.md`). 에뮬레이터에서의 동작 확인이 아니라 "메서드가 없다"는 확인이다.

| 모르는 것 | 확인한 것 | 그래서 앱이 하는 일 |
|---|---|---|
| 터널 안인지 | SDK 에 신호 없음 | 알 수 없으므로 묻는다. 맡긴 뒤에도 예고하고 5초 동안 취소를 받는다 |
| 바깥 공기질 | SDK 에 신호 없음 | 위와 같다. 바깥 농도는 고정값(430ppm)으로 계산하고, 차가 내외기를 자동 조절 중이면 숨은 제어하지 않는다. v0.7.0 부터 초미세먼지만 날씨 서비스의 넓은 격자 모델값을 참고한다(I 절). 그 자리의 공기는 여전히 모른다 |
| 시동(점화) 상태 | SDK 에 API 없음 | 세션의 시작과 끝을 기어와 주차브레이크 텔테일로 본다 |
| 차량 속도 | SDK 에 API 없음 | 숨 모델은 속도를 쓰지 않는다. 정차·정체 때는 추정이 실제보다 낮을 수 있다. 위치 차이로 어림한 속도는 실험 중인 핸들 보조 신호의 조건에만 쓴다 |
| 바깥 온도 | SDK 에 API 없음 | 온도에 따라 묻는 방식을 바꾸지 않는다. 졸음 개입의 "찬 바람"은 설정 온도를 2도 내리는 것까지다 |

함께 적어 두는 것
- 숨은 사람이 내쉰 이산화탄소만 추정한다. 배기가스(일산화탄소)는 알 수 없다. 쉼 카드 아래에 같은 문장을 늘 적어 둔다.
- 내비 목적지의 남은 시간(remainTime)은 SDK 에 단위 표기가 없다. 앱이 남은 거리와의 비율로 초인지 분인지 가린다. 에뮬레이터 확인 전이다.
- 창문 위치 값의 방향(닫힘이 min 인지 max 인지)은 실측 전이다. 그래서 창문 열기는 기본에서 뺐다.
- 문서에 쓰는 한계 문장(그대로): "숨은 터널이나 바깥 공기질을 알 수 없다. 그래서 묻고, 맡긴 뒤에도 예고하고 취소를 받는다."
- Pleos 에뮬레이터 실측은 여전히 0건이다.

## I. 숨 설계 근거 (v0.7.0, 2026-11-11)

대상은 v0.7.0 "숨 설계"다. 지금까지의 "CO2 추정 → 2분 환기 제안"을 CO2 와 바깥 미세먼지를 저울질하는 여정 환기 계획으로 넓혔다. 한 줄로 말하면 이렇다. 내기만 쓰면 CO2 가 쌓이고, 외기만 쓰면 미세먼지가 들어온다. 숨은 둘 사이에서 덜 손해 보는 때와 길이를 고른다.

확인 수준: 이 절의 논문은 조사 단계에서 서지와 초록 수준으로 확인한 것이다. 원문 전문을 열어 표와 본문 수치를 직접 대조하지 못했다. 그래서 "원문 인용" 칸은 비워 두고, 판정 칸에 "서지와 초록 수준 확인"이라고 적었다. v0.7.0 구현 작업에서 직접 열어 본 것은 I-6 의 Open-Meteo 문서뿐이다. 기획서, 발표, 영상에 이 절의 수치를 쓰려면 먼저 원문을 열어 확인한다. 여기 적지 않은 수치나 인용문은 쓰지 않는다.

앱이 한 단순화와 한계
- 시각 성분: 04시에 1, 반폭 5시간(23시~09시)인 봉우리와 15시에 0.35, 반폭 2.5시간인 작은 봉우리 가운데 큰 쪽. 높이와 폭은 자체 설정이다.
- 시간 성분: 운전자가 몇 시에 일어났는지, 얼마나 잤는지 모른다. 그래서 깨어 있던 시간(S) 대신 연속 주행 시간으로만 어림한다(120분에서 1). 밤새 깨어 있다가 막 출발한 사람은 낮게 나온다.
- 합: 0.7 × 시각 + 0.3 × 연속 주행. 0.5 이상이면 화면에 "졸리기 쉬운 시간대"라고 표시한다.
- 쓰는 곳: 화면 표시와, 졸음 제안에서 쉼터 경유를 먼저 실행하는 순서뿐이다. 환기 한도를 낮추는 규칙은 "야간 장거리 0.8배"(자체 설정) 그대로다. 이 값으로 제안 시점을 바꾸지 않는다.
- 이것은 졸음을 알아내는 기능이 아니다. 운전자를 보거나 재지 않는다. "졸리기 쉬운 시간대"라고만 쓴다.

이 작업 환경에서는 API 의 실제 응답 본문을 받아 보지 못했다(프록시에서 연결이 끊겼다. 잘못된 좌표에 대한 오류 응답은 받았다). 응답 읽기는 Open-Meteo 의 공통 형식(`{"current":{"pm2_5":값,"pm10":값}}`)을 기준으로 만들었고, 형식이 다르면 값 없음으로 처리한다. 에뮬레이터에서 자가 진단의 "바깥 공기" 줄로 확인한다.

보내는 것: 위도와 경도를 소수 첫째 자리로 반올림한 값 둘뿐이다(약 10km). 키, 기기 정보, 계정 정보는 보내지 않는다. 30분에 한 번 받는다.

### I-7. 모델 기본값

실내 PM2.5 추정식: dP/dt = k × (P_out × IO - P). P 는 실내, P_out 은 바깥(µg/m³), IO 는 그 모드에서 오래 두면 닿는 실내/실외 비, k 는 그 값으로 다가가는 속도(회/시간). 노출량은 P 를 시간으로 적분한 값(µg/m³·분)이다. 전부 추정이다.

| 값 | 기본값 | 근거와 한계 |
|---|---|---|
| pmIoRecirc | 0.15 | I3 의 내기 범위 0~0.4 안. I4 의 0.10~0.13 보다 조금 높게 잡았다(내기의 이득을 과하게 잡지 않는 쪽) |
| pmIoFresh | 0.6 | I3 의 외기 범위 0.6~1.0 의 아래 끝이고 I5 의 오래된 필터 값. 새 필터(0.20)인 차에서는 실제보다 높게 나온다 |
| pmIoWindow | 1.0 | 창문으로 들어오는 공기는 필터를 거치지 않는다고 본 자체 가정 |
| pmRecircAch | 20회/시간 | 자체 가정. 내기순환에서 실내 공기가 필터를 거쳐 도는 속도를 고정값으로 둔 것이다. 실측 근거가 없다. 풍량에 따라 달라지지만 반영하지 않았다 |

질량 수지에서 쓰는 성질: 바깥 공기를 같은 양 들일 때 빠지는 CO2 는 (실내 농도 - 그 조건의 평형 농도)에 비례한다. 그래서 CO2 가 높을 때 바꾸는 것이 같은 미세먼지 값으로 CO2 를 더 많이 뺀다. 엔진 테스트(`BreathModelTest`)가 이 비례를 확인한다. 이것은 숨 모델 식에서 나오는 계산이고 실차에서 잰 것이 아니다.

|---|---|---|---|
| 값 없음, 보통 | v0.6.2 와 같다 | 2분 | 이벤트가 v0.6.2 와 하나도 다르지 않다(테스트로 견줌) |
| 좋음 | v0.6.2 와 같다 | 2분 | 2분 환기 뒤 10분 안에 다시 닿으면 "바깥 공기로 바꿔 둘까요?" |

한도를 정하는 순서: 기본 한도 2,000ppm → 야간 장거리면 0.8배 → 바깥 미세먼지가 나쁨 이상이면 그 여유를 없애고 기본 한도로. 어떤 경우에도 기본 한도보다 높아지지 않는다.

### I-8. 검산 (기본값, 풍량 3/8, 엔진 테스트와 화면 표본에서 얻은 값)

- 혼자, 나쁨: 한도 2,000ppm 에서 "1분만 짧게". 되돌릴 때 추정 약 1,300ppm.
- 2명, 나쁨: "1분 30초만 짧게", 약 6분마다. 값이 없을 때는 2분.
- 4명, 나쁨: 2분으로도 목표에 못 닿아 "2분만"(짧게를 붙이지 않는다). 값이 없으면 처음부터 "바깥 공기로 바꿔 둘까요?".
- 혼자, 한 시간, 값 없음: 환기 약 3번, 첫 번째는 약 20분 뒤.
- 세 갈래 비교 표본(2명, 한 시간, 바깥 PM2.5 41µg/m³, 제안에 전부 동의): CO2 최고 추정은 내기만 5,645 / 외기만 754 / 이번 주행 2,017ppm. 실내 PM2.5 평균 추정은 내기만 7.1 / 외기만 25 / 이번 주행 13µg/m³. 화면 표본 `docs/shots/16_도착카드_세갈래.png` 와 같은 값이다.
- 이 숫자는 전부 모델 계산이다. 실차에서 잰 값이 아니고, 이 차의 필터 상태를 모른다.

### J-3. 프로필은 설정이다

프로필별 숫자(환기를 묻는 시점을 한도의 90%로, 쉬는 간격을 90분으로, 미세먼지 등급을 한 단계 나쁘게)를 뒷받침하는 문헌은 확인하지 못했다. 그래서 프로필은 기준이 아니라 사용자가 고르는 설정이다. 하는 일은 셋뿐이다.

| 프로필 | 바뀌는 것 | 근거 |
|---|---|---|
| 어린이, 임산부 | 공기 여유 넓게: 환기를 묻는 시점을 한도의 90%로 당긴다(`airMarginFraction`) | 없음. 자체 설정. 조금 일찍 묻자는 선택이다 |
| 호흡기 주의, 심혈관 주의 | 미세먼지 먼저: 바깥 등급을 한 단계 나쁘게 보고 환기를 늦추고 짧게 한다. CO2 기본 한도는 넘기지 않는다 | 없음. 자체 설정. J1 은 "차 안 미세먼지를 줄이는 쪽이 손해가 아니다"는 배경으로만 읽는다 |
| 임산부, 어르신, 심혈관 주의 | 쉬는 간격을 90분으로 줄인다(`sitBreakMinutesShort`). 기본은 120분 | 120분은 J3(A5). 90분은 근거 없음. 자체 설정 |

화면과 문서에 적는 문장(그대로): "이 자리 설정으로 환기와 쉼의 순서가 바뀌어요. 의학적 조언이 아니에요."

앉은 시간은 몸을 잰 값이 아니다. 좌석 점유 값, 기어, 문 열림 경고등으로 "앉아 있었다, 일어섰다"만 가린다. 쉼터에서 5분 넘게 서 있었으면 "걷기 쉼 1회"로 적지만 실제로 걸었는지는 알 수 없다. 자리별 누적은 차 안 공기를 한 덩어리로 계산한 값을 자리마다 탄 시간만큼 나눠 적은 것이다. 자리마다 농도가 다르다고 계산한 것이 아니다.
